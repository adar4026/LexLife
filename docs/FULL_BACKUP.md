# Документы анализов, полная резервная копия и импорт подготовленного анализа

Всё работает локально, без интернета и внешних сервисов. Файлы никуда не отправляются.

## 1. Документы анализов (PDF / фото)

- Форматы: PDF, JPG/JPEG, PNG, HEIC/HEIF. Тип определяется по содержимому файла (сигнатуре), а не по имени. Лимит — 15 МБ.
- Сам файл хранится в **IndexedDB** браузера: база `lexlife-files`, хранилище `attachments`, запись
  `{ id, testId, name, type, size, addedAt, data: ArrayBuffer }`. В `localStorage` файлы не попадают.
- В записи `health_tests` — только метаданные (не более одного документа на анализ):
  ```jsonc
  "attachments": [ { "attachmentId": "att_…", "name": "Анализ.pdf", "type": "application/pdf", "size": 182734, "addedAt": "ISO" } ]
  ```
- Удаление анализа удаляет его документ. Удаление документа (форма «Изменить» → «Удалить» → «Сохранить») оставляет анализ.
- При запуске приложения фоном удаляются «висячие» файлы — на которые не ссылается ни один анализ. Безопасность очистки:
  анализы читаются строго (ключа нет / JSON повреждён / идёт восстановление → ничего не удаляется), файлы моложе 10 минут не трогаются.
- Если метаданные есть, а файла на устройстве нет (например, после восстановления обычной копии на другом устройстве),
  карточка показывает документ, а при открытии — понятное сообщение.

Код: `js/services/attachments.js`.

## 2. Полная резервная копия с документами (ZIP)

Экран «Резервная копия» → **«Полная резервная копия с документами»**. Файл `LexLife-full-backup-ГГГГ-ММ-ДД-ЧЧММ.zip`.
Восстановление — той же кнопкой «Восстановить из копии» (ZIP распознаётся автоматически).

Состав архива (ZIP без сжатия, метод STORE, UTF-8 имена; свой код без CDN — `js/services/zip.js`):

```
lexlife-full-backup.json     манифест
backup.json                  обычная резервная копия LexLife (backupFormatVersion 2, тот же JSON,
                             что «Создать резервную копию»)
attachments/<attachmentId>.<pdf|jpg|png|heic|heif>   исходные файлы анализов без изменений
visit-attachments/<attachmentId>.<…>                 документы медицинских записей («Врачи и визиты»)
```

Манифест:
```jsonc
{
  "app": "lexlife",
  "kind": "lexlife-full-backup",
  "fullBackupFormatVersion": 1,
  "createdAt": "ISO",
  "appVersion": "1.0.0",
  "backup": "backup.json",
  "attachments": [
    { "attachmentId": "att_…", "testId": "…", "name": "Анализ.pdf", "type": "application/pdf",
      "size": 182734, "addedAt": "ISO", "file": "attachments/att_….pdf" }
  ],
  "visitAttachments": [   // необязательный; копии до документов записей его не содержат
    { "attachmentId": "att_…", "visitId": "…", "name": "Заключение.pdf", "type": "application/pdf",
      "size": 90211, "addedAt": "ISO", "file": "visit-attachments/att_….pdf" }
  ]
}
```

Совместимость:
- Обычная копия (JSON) не изменилась: формат 2, схема 8, поле `blobs: {}`. Новые поля анализов (`attachments` с метаданными,
  `customResults`, `labRanges`, `importId`) — дополнительные; старые версии LexLife их принимают и просто не показывают.
- `backup.json` из ZIP можно извлечь и восстановить как обычную копию (без документов) — в том числе старой версией.
- Старые копии (формат 1, схемы < 8, анализы без вложений) восстанавливаются как раньше.
- `visitAttachments` — аддитивный список: `fullBackupFormatVersion` остался 1, старые версии LexLife его не читают
  (данные и документы анализов восстанавливают как прежде), полные копии без него восстанавливаются новой версией без ошибок.

Восстановление полной копии:
1. Проверка без записи: архив, CRC каждого файла, манифест, `backup.json` (та же проверка и миграции в песочнице, что у обычной копии),
   соответствие документов описанию (id, тип, размер).
2. Предпросмотр с числом документов и предупреждением о замене текущих данных.
3. Документы записываются в IndexedDB (прежние пока не удаляются); ошибка → добавленные удаляются, данные не меняются.
4. Атомарная замена данных `localStorage` с защитной копией и откатом (как у обычной копии); ошибка → добавленные документы удаляются.
5. Удаляются документы, не привязанные к восстановленным анализам / записям.

Обычная копия (JSON) документы не содержит: после её восстановления файлы текущих анализов, которых нет в копии, будут удалены
как «висячие» (предпросмотр предупреждает, сколько).

Код: `js/services/fullBackup.js`.

## 3. Импорт подготовленного анализа (JSON)

Экран «Анализы» → **«Импортировать подготовленный анализ»** → выбрать файл в «Файлах».
Файл проверяется, показывается предпросмотр, запись **добавляется** к существующим анализам.
Другие данные (вода, лекарства, показатели, настройки, прежние анализы) не меняются.
Повторный импорт той же записи блокируется по `importId` (и при двойном нажатии — операции над анализами выполняются по очереди).

```jsonc
{
  "app": "lexlife",
  "kind": "lexlife-prepared-test",
  "formatVersion": 1,
  "importId": "prepared-…",            // 8–100 символов: латиница, цифры, . _ : -
  "test": {
    "date": "ГГГГ-ММ-ДД",
    "note": "…",                        // необязательно
    "chol": 0, "ldl": 0, "hdl": 0, "trig": 0, "glucose": 0,
    "hba1c": 0, "vitd": 0, "tsh": 0, "psa": 0, "hgb": 0, "hct": 0,   // основные поля формы, в единицах формы
    "labRanges": { "ldl": "0.00–116.00 mg/dL" },                        // диапазоны лаборатории для основных полей
    "customResults": [                                                 // всё, чего нет среди основных полей
      { "group": "Гематология", "name": "…", "value": 0, "unit": "…", "ref": "4.00–11.00" },
      { "group": "Анализ мочи", "name": "…", "text": "отрицательно", "unit": "mg/dL", "ref": "" }  // качественный результат
    ]
  }
}
```

У показателя — либо число `value`, либо текст `text` (качественный результат бланка: «отрицательно», «норма»; до 60 символов),
но не оба сразу. Текстовые результаты показываются в карточке как есть и не попадают в графики истории. Показатели группы
«Анализ мочи» (`моч`/`orina`/`urin` в названии группы) и «Кал» (слово «кал»/«кала» или `heces`/`stool`/`fecal`/`копрогр` в названии группы)
выводятся отдельными разделами и не смешиваются с одноимёнными показателями крови.
Стандартные показатели мочи (pH, удельный вес, белок, глюкоза, нитриты, кетоны, уробилиноген, билирубин,
гемоглобин/миоглобин, осадок) распознаются по названию (рус./лат./исп.) и получают общий ключ истории `urine_*`,
поэтому «pH» и «pH мочи» из разных бланков попадают в один график. Название в файле можно оставить как на бланке.

Разрешены только перечисленные поля (неизвестное поле — ошибка, чтобы в запись не попали, например, персональные данные).
Для простого числового диапазона `a–b` дополнительно сохраняются `refLow/refHigh`, и в карточке значение вне диапазона лаборатории
помечается нейтральной стрелкой ↑/↓. Текстовые пояснения лаборатории сохраняются как есть. Диагнозов и рекомендаций приложение не делает.

Личные файлы с анализами держите в `private/` (папка в `.gitignore`) — никогда не в исходном коде, тестах или коммитах.

Код: `js/services/preparedImport.js`. Тесты: `node tests/attachments.test.mjs` (только синтетические данные).

## 4. Документы медицинских записей («Врачи и визиты»)

Карточка записи → раздел **«Документы»** → «Добавить файл» (iOS предлагает «Медиатека», «Снять фото», «Выбрать файлы»; можно несколько сразу).
PDF, JPG/JPEG, PNG, HEIC/HEIF до 15 МБ каждый, тип — по сигнатуре содержимого. Просмотр — тот же `ui/docViewer.js`, что у анализов
(PDF все страницы, фото полноэкранно, «Поделиться»/«Сохранить»). Удаление одного документа запись не удаляет; удаление записи удаляет её документы.

- Файлы — в **отдельной** базе IndexedDB `lexlife-visit-files` (хранилище `attachments`, запись `{ id, visitId, name, type, size, addedAt, data }`).
  Отдельная база выбрана намеренно: очистка «висячих» документов анализов (и в старых версиях LexLife) смотрит только на `lexlife-files`
  и не может удалить файлы записей.
- В `health_visits[i].attachments` — только метаданные `{ attachmentId, name, type, size, addedAt }`, без base64. Документы дописываются
  к уже прикреплённым (`Storage.addVisitAttachments`), удаляются по одному (`Storage.removeVisitAttachment`).
- Записи из импорта медицинской истории создаются без документов; файл прикрепляется к любой старой записи позже, без пересоздания записи.

Код: `VisitAttachmentService` в `js/services/attachments.js`. Тесты: `tests/visit-attachments.test.mjs`.

## 5. Импорт медицинской истории (JSON)

Настройки → «Импорт медицинской истории» (`#/history-import`). Файл `kind: lexlife-medical-history`, `formatVersion: 1`:
`events[]` (визиты, процедуры, обследования, стоматология, заболевания… → `health_visits`, поля `kind/title/time/importId`) и
`meds[]` (курсы → `health_meds`). Результаты анализов этот формат не принимает.
Курс принимается только с датой окончания и статусом `courseStatus`: `completed` (завершён), `stopped` (прекращён досрочно),
`prescribed` (назначен, приём доз не отмечался) — поле аддитивное, показывается в «Завершённых курсах»; отметки приёма (`med_intakes`)
импорт не создаёт. Начало приёма без известного окончания — событие `kind: medication` («Начало приёма»), а не курс: иначе
препарат считался бы активным сейчас. «Запись к врачу» (`kind: appointment`) в карточке отмечена как запись, а не состоявшийся визит.

- Проверка без записи (dry-run): реальные локальные даты не в будущем, известные поля и виды; любая ошибка отклоняет весь файл.
- План: добавить / уже есть (дубль: дата + врач/вид/процедура/зуб по ключевым словам; «Сдача анализов» — дубль, если есть анализ той же даты;
  курс — препарат с синонимами + дата начала) / требует уточнения (тот же препарат без даты начала или с пересекающимся периодом) /
  импортировано ранее (`importId`; удалённое вами не возвращается).
- Применение — только слияние: разделы перечитываются перед записью, новые записи дописываются в конец; после записи проверяется, что все прежние
  записи остались неизменным префиксом списка; иначе убираются только добавленные. Перед импортом — резервная копия. Повторный импорт → 0.
- Реальные файлы истории хранятся только в `private/` (в `.gitignore`, в сборку не попадает).

Код: `js/services/historyImport.js`. Тесты: `tests/history-import.test.mjs`.
